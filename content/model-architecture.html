01 · Transformer 架构解析

Transformer 的核心不是某一层的名字，而是“表示如何在层间流动”。输入先变成向量，位置信息进入表示，注意力建立 token 间关系，前馈网络做逐 token 的非线性变换，残差和归一化让深层训练保持可控。

三种骨架

Encoder-only
每个位置可看见双向上下文，适合表示、分类和检索编码。输出是一组上下文化表示，不直接规定自回归生成。
Decoder-only
用因果 mask 让位置只能看见当前位置及之前的 token，按 next-token objective 逐步生成。GPT 家族属于这种主流范式。
Encoder–Decoder
Encoder 读取完整输入，Decoder 用因果注意力生成输出，并通过 cross-attention 读取 Encoder 表示，适合明确的输入到输出任务。

表示进入模型前后

tokenizer 将文本映射成整数 ID；embedding 将 ID 映射为向量。位置可以通过绝对位置向量、RoPE 等相对旋转机制注入。最后一层隐状态经过词表投影和 softmax 得到下一个 token 的概率分布。

生成阶段只保留需要的 KV 表示，形成 KV Cache；它减少重复计算，却会把上下文长度转化为显存压力。模型架构与服务配置共同决定实际吞吐。

注意力、FFN、残差与归一化各自解决什么？

部件数据流解决的问题代价与边界
Self-AttentionQ 与所有合法 K 做相似度，按权重汇总 V建立远距离 token 关系全注意力的 token 对数量随长度平方增长；KV Cache 和分块策略影响服务成本
Cross-AttentionDecoder 的 Q 读取 Encoder 的 K/V把输入条件接入生成增加一组跨序列计算；Decoder-only 通常用上下文拼接代替
FFN对每个 token 独立做升维、非线性、降维储存和变换特征，补足注意力的混合能力中间维度带来参数和 FLOPs；激活函数与门控改变稀疏程度
Residual + Norm归一化后的更新与旧表示相加控制尺度并让梯度有稳定主路归一化位置、统计方式和精度会影响深层稳定性；它们不能修复数据或目标本身的问题

02 · 现代架构组件

现代模型的变化通常发生在同一个预算问题上：在给定训练算力、显存、上下文和延迟下，怎样保留有效表达能力。下面按“输入怎样流过组件”解释位置、归一化、注意力、FFN 和 MoE。

位置从“加向量”变成“旋转关系”

数据流：Q、K 在投影后按位置角度旋转，再参与点积；相对位置信息自然体现在相位差中。YaRN 通过缩放和校准把训练长度外推到更长上下文；Partial RoPE 只在部分维度施加旋转。

取舍：长上下文可用范围扩大，但外推不是免费增加训练信息，仍要用长上下文评测检查远端检索、局部顺序和数值稳定性。具体模型是否采用某种 YaRN 参数：待核实。

用户画板 图中机制；外部算法细节属于通用解释，具体实现版本待核实。

让更新可加回主干

数据流：RMSNorm 用均方根缩放向量，不计算均值；子层输出再与残差输入相加。Pre-Norm 把归一化放在子层前，形成更直的梯度路径。

取舍：RMSNorm 计算更简洁、适合大规模训练；它不等于更高质量，也不能替代初始化、学习率和数据质量。残差增加主干带宽与激活保存，但通常换来深层优化稳定性。

用户画板 图中机制；不同模型的 Norm 次序与 epsilon：待核实。

注意力是在算力和记忆之间换预算

数据流：MHA 为每个 head 保存独立 K/V；MQA 共享一组 K/V；GQA 让一组 query heads 共享一组 K/V；MLA 进一步把 KV 压到潜在表示再恢复。DSA、SWA 等稀疏或滑窗方法限制可见范围，减少长序列计算。

取舍：共享 KV 降低 KV Cache 显存与带宽，但可能损失头间多样性；滑窗/稀疏注意力降低平方项，却需要额外的全局通道或检索策略。某一模型到底采用 MHA、GQA、MLA、DSA 或 SWA：按版本待核实。

用户画板 图中比较；模型版本字段以官方技术报告为准。

门控激活把“是否通过”纳入表示变换

数据流：SwiGLU 将一条线性支路作为候选值，另一条经 SiLU 后作为门，两者逐元素相乘再投影回 hidden。Gated Attention 让注意力输出经过额外门控后再回到残差主路。

取舍：门控提升表达的选择性，但中间投影和激活缓存提高参数、FLOPs 或显存；门控尺度与归一化需要联合调校。是否启用 Gated Attention：待核实。

用户画板 图中机制；激活和门控组合不是所有模型的共同配置。

参数总量与每 token 计算量分离

数据流：Router 为每个 token 计算专家分数，选择 Top-K 专家；专家分别处理 token，结果按门控权重合并。共享专家可提供所有 token 都经过的稳定通道，辅助专家负责稀疏容量。

取舍：激活参数量下降，模型总容量可以上升；代价是 all-to-all 通信、专家负载不均、容量溢出和路由抖动。负载均衡损失、容量因子和 token 丢弃策略会影响训练稳定性与推理尾延迟。

04 · 训练与后训练

训练不是一条把数据送进模型的直线，而是目标、数据、评测和资源共同反馈的循环。Pre-training 建立通用能力，SFT 调整示例行为，偏好或奖励优化改变输出选择；LoRA 是参数更新方式，与 PPO、DPO、GRPO 属于不同层次的概念。

目标层次

  • Pre-training：在大规模语料上预测下一个 token，建立语言和世界知识的统计基础。
  • SFT：用输入—输出示例监督目标回答格式、任务行为和风格。
  • LoRA：冻结主模型，在低秩矩阵中学习增量参数；它是更新方式，可与 SFT 或偏好目标组合。
  • PPO：用奖励模型、价值模型和裁剪策略做在线策略优化，工程链路重但反馈灵活。
  • DPO：直接用偏好对优化相对偏好，省去显式在线 RL 的部分组件，但依赖偏好数据质量和参考模型设定。
  • GRPO：以组内相对奖励估计优势，减少对独立 value model 的依赖；具体采样、规则奖励和稳定化技巧依实现而定。

数据和优化细节

JSONL 只是容器；字段需要稳定，特殊 token（如 system、user、assistant 或工具边界）必须与 tokenizer 约定一致。Prompt masking 规定哪些位置作为条件，loss masking 规定哪些 token 计入损失，二者不等价。工具调用数据还要保留调用参数、结果和错误路径，避免只训练“漂亮答案”。

梯度累计在显存有限时用多个 micro-batch 近似更大的有效 batch；学习率调度决定 warmup、峰值和衰减；它们都会改变收敛速度和稳定性，不能把一次 loss 下降解释为能力提升。

05 · Agent 与 JEV 决策模型

Agent 是基础模型外加工具、状态、循环和约束的系统。模型负责提出下一步动作候选，运行时负责验证、执行、记录和停止。JEV 放在这个决策层：它讨论的是类型化决策与置信度如何进入系统控制面，而不是又一个 Transformer 组件。

五层演进

  1. Base model：只产生文本或结构化候选。
  2. Tool use：模型学会输出符合 schema 的调用请求，运行时执行工具并返回结果。
  3. Workflow state：把事实、事件、计划、权限和进度分开存储，避免把临时文本当正式状态。
  4. Agent loop：在 plan、act、observe、verify 之间循环，并设置预算、超时和停止条件。
  5. Decision layer：对动作类型、概率、置信度和升级路径做明确决策，再交给执行器。

为什么类型比“多生成几次”更重要？

字符串相似度不足以表达“这是一个可执行动作、一个待确认事实，还是一个需要升级的人机决策”。类型系统让结果有明确字段、枚举、前置条件和失败分支；概率表达不确定性，置信度表达经过哪些校验。二者可以一起进入路由，也可以因业务需要分别校准。

类型和概率都不保证正确：工具的副作用、权限边界、数据新鲜度和评测集仍需要独立验证。

Architectural interpretation · 系统解释

从系统设计角度，JEV 可以被放在 Agent loop 与执行器之间：模型提出候选，JEV 负责将候选映射到已定义的决策类型，结合概率/置信度和上下文约束选择继续、重试、降级或请求人工确认。它更像控制面和决策协议，具体算法、参数和部署方式需以 TypeSafe 的完整文档为准。
