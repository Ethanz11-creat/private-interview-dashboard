01 · 读懂 Transformer：一句话在模型里经历了什么

设想我们把“联想的总部位于”交给模型，希望它接着生成一个地点。整个过程只有一条主线：把已有文字编码成表示，让每个位置读到相关上下文，不断更新表示，最后把末尾位置的表示变成词表上的分数。

先分清 token、向量和概率的关系

模型并不直接接收汉字。Tokenizer 把文本切成 token，再查表得到整数 ID；一个 token 可能是一个字、一个词的片段或标点，具体切法取决于词表。Embedding 是一个可以学习的矩阵 E，形状为 [词表大小 V, 隐藏维度 d]。查到 ID 就取出 E 的对应行，因此“一个 token”变成了“d 个浮点数”。这些数是模型学习到的表示，不是预先规定好含义的标签。

假设输入被切成 6 个 token，隐藏维度取 4，便得到一个 X ∈ ℝ⁶×⁴ 的矩阵。每一行属于一个位置，每一列属于表示中的一个维度。实际模型的 d 通常是几千；训练时还有 batch 维度 B，所以常见输入形状是 [B, T, d]。后续模块会改变每一行的内容，却通常保持主干的这个形状，方便逐层相加。

注意力把“我在读什么”变成一次可学习的加权读取

刚查表时，同一个 token 在不同句子中的向量基本相同。例如“苹果发布新品”和“苹果很甜”中的“苹果”，需要上下文才能区分。Self-Attention 让当前位置的向量向其他位置读取信息：同一份 X 经过三组可学习的投影，得到 Q = XW_Q、K = XW_K、V = XW_V。Q 是当前位置用于匹配的特征，K 是每个候选位置被匹配的特征，V 是匹配成功后真正读出的内容。Q/K/V 的名字只是帮助理解，实际数值全部由训练学习。

以一个 head 为例，Q 和 K 的形状都是 [T, d_h]。QKᵀ 得到 [T, T] 的分数矩阵：第 i 行第 j 列表示位置 i 对位置 j 的关注程度。除以 √d_h 是为了控制点积的尺度，避免维度增长导致 softmax 太容易饱和。加入 mask 后，对每一行做 softmax，把分数变成总和为 1 的权重；再乘 V，得到每个位置的上下文混合表示。

Attention(Q,K,V) = softmax(QKᵀ / √d_h + M) VQ/K 决定读哪里，V 决定读回什么；M 决定哪些位置允许被读。

如果末尾位置对三个合法位置的权重是 [0.1, 0.7, 0.2]，它的新表示就是 0.1v₁ + 0.7v₂ + 0.2v₃。这不是直接复制某个词，而是混合几个向量。多头注意力重复多组这样的读取，让不同子空间学习不同关联，最后拼接并经过输出投影 W_O，回到 d 维主干。某个 head 偶尔表现出语法或实体关系偏好，但没有人工给每个 head 指定固定职责。

因果 mask 与三种 Transformer 骨架

训练自回归生成时，位置 i 的目标是预测位置 i+1。如果它能读到后面的正确答案，训练就变成了作弊。因此 Decoder-only 使用下三角可见区域：未来位置在 softmax 前加上负无穷，使其权重变为 0。这仍允许训练时并行计算所有位置；“不能看未来”约束的是数据依赖，不是必须逐 token 串行训练。

Encoder-only 则让每个位置读到双向上下文，适合获得整句表示、做分类或检索编码。Encoder–Decoder 的 Encoder 双向读取输入；Decoder 除了因果 self-attention，还增加 cross-attention：Q 来自 Decoder，K/V 来自 Encoder。这让“读输入”与“生成输出”有明确分工。现在很多聊天模型采用 Decoder-only，把指令、文档和问题放在同一段上下文里，通过因果读取完成条件生成。

一层里面有两次更新：读上下文，然后加工当前位置

注意力解决了 token 之间的信息交换，但还需要把得到的特征加工成更有用的表示。FFN 对每个位置独立使用同一套参数，做升维、非线性变换和降维。普通形式是 FFN(x) = W₂ φ(W₁x)；它不会直接跨位置交换信息。注意力像从上下文取材料，FFN 像加工材料，两者交替出现，多层后表示能够组合出更复杂的关系。把 FFN 理解成一个“知识数据库”只是比喻，事实与能力分布在整个网络里。

u = x + Attention(Norm(x))y = u + FFN(Norm(u))这是常见的 Pre-Norm 层。两次 Norm、两次残差相加都各有位置。

Residual 保留已有表示，只让子层学习一个增量。沿反向传播看，∂y/∂x 包含来自恒等支路的项，给梯度提供直接路径；不过整条深层链路仍可能出现尺度问题，残差并不自动保证训练稳定。Norm 负责控制每个 token 的特征尺度，让子层更容易处理不同输入。两者合作，模型才比较容易堆到几十层甚至更多。

最后一步生成 token；训练和推理在这里分开

经过 L 层后，最后的隐状态 h 经输出矩阵映射到 V 个词表分数，即 logits。Softmax 将它们变成候选概率；采样、temperature、top-p 等策略决定选哪一个 token。选出的 ID 被追加到输入，模型继续预测下一个 token。概率表示模型在上下文里的预测倾向，不等于这句话在现实世界中为真的概率。

训练时，通常把文本右移一位作为标签，同时计算各位置的交叉熵：ℒ = −Σ log p(xₜ | x₍＜t₎)。生成时，先用 prefill 处理整个提示词并构建每层 KV Cache；随后 decode 每次处理一个新 token。因果结构保证历史位置不会因为未来新增 token 而改变，所以历史 K/V 可以缓存，不必每步重算。新 token 的 Q 仍要读取历史 K/V，长上下文依旧会增加读取成本。

02 · 拆开关键组件：不同设计到底省了哪笔预算

现代模型大多保留“注意力更新 + 前馈更新”的主干，变化主要发生在位置表达、历史记忆、token 交互和专家计算这几处。读新名字时，先找到它改动的是哪一个模块。

RoPE：把位置关系放进 Q 与 K 的点积

如果只给一组 token 向量而不给顺序，注意力无法可靠地区分“甲支持乙”和“乙支持甲”。RoPE 将 Q/K 中成对的维度视为二维向量，让位置 m 的向量旋转 mθ。某一对维度的转换是 [a cos(mθ) − b sin(mθ), a sin(mθ) + b cos(mθ)]。不同维度对使用不同频率，组合起来表达多种距离尺度。

关键在于点积：位置 m 的 Q 与位置 n 的 K 都旋转后，内积里的位置影响依赖 n−m。这样，模型能在“内容匹配”里同时感知相对距离。RoPE 通常不旋转 V；Partial RoPE 只旋转 Q/K 的部分维度，保留其余维度做内容表达。YaRN 等方法调整不同频段的旋转尺度并校准注意力，以帮助扩展上下文；配置里写了更大的长度，仍需要长文本检索和任务评测验证效果。

RMSNorm 与 SwiGLU：先稳住尺度，再做有选择的特征变换

RMSNorm 对单个 token 的 d 维向量计算均方根，然后逐维乘可学习的缩放系数：Norm(x) = γ ⊙ x / √(mean(x²) + ε)。它不减去均值；LayerNorm 则还会减均值并按方差归一化。这里的归一化沿特征维进行，不是把所有 token 混在一起归一化。放在 Attention 和 FFN 前面，让这两个更新分支接收较受控的尺度。

SwiGLU 的计算可以写成 W_down[SiLU(W_gate x) ⊙ (W_up x)]，其中 SiLU(z) = z·sigmoid(z)。两条升维投影分别提供门控信号和候选特征，逐元素相乘后再降维。门是连续数值，不是严格的 0/1 开关。它让特征通过量依赖输入，比单条非线性支路更灵活；代价是三组投影矩阵和中间激活。Dense FFN 与 MoE 专家内部都可以使用 SwiGLU。

MHA、GQA、MLA：改变历史 K/V 怎么存

MHA 为每个 Q head 配独立的 K/V head。GQA 保留较多 Q heads，却让同一组 Q 共享少量 K/V heads；MQA 是只留一组 KV 的极端情形。比如 32 个 Q heads 配 8 个 KV heads，每 4 个 Q heads 共用一组 KV，缓存的 K/V 数量降为 MHA 的四分之一。每个 Q 的匹配权重仍可不同，因此共享 KV 并不是所有 head 读出同一个结果。

KV Cache 字节数 ≈ B × T × L × 2 × H_KV × d_h × sB：并发序列数；T：缓存长度；L：层数；2：K 和 V；s：每个元素字节数。此式适用于标准 K/V 缓存。

取 B=1、T=8192、L=32、d_h=128、FP16 的 s=2。若 H_KV=32，缓存约 4 GiB；若 H_KV=8，约 1 GiB。并发数或长度翻倍，缓存也相应翻倍。这还没计模型权重、激活和运行时额外开销。GQA 主要缓解 decode 时的显存占用与带宽，不能让全注意力的 token 配对数量自动变成线性。

MLA 走另一条路：先把每个 token 的 KV 信息下投影成低维 latent c_t，再由它形成多个 head 的内容 K/V；位置分量单独处理。优化的推理实现可以通过矩阵吸收等方式在压缩空间里计算，缓存 c_t 与 RoPE 分量，避免展开并永久保存完整多头 KV。DeepSeek V3 的相关配置是 512 维 KV latent 与 64 维位置分量；典型缓存口径约为每 token、每层 (512+64)×s，不再使用标准多头 KV 公式直接估算。具体收益仍取决于推理引擎实现和缓存精度。

SWA、DSA 与 DeltaNet：改变历史怎么被读取

SWA 为每个 query 只保留最近 w 个位置，长序列中的注意力配对数可从 T² 降到约 Tw。它天然偏向局部关系。混合结构会穿插全注意力层，让远距离信息还有直接连接通路；否则远端信息只能靠多层间接传播，长距离任务容易受影响。

DSA 使用一个较轻量的 indexer 为当前 query 选出重要的历史位置，再在这些位置上执行主注意力。它不是“永远读最近的窗口”：远端位置也可能被选中。MLA 压缩缓存内容，DSA 减少主注意力读取的位置，两者针对的是不同成本，可以同时采用。主注意力部分的开销随所选位置数缩小，但 indexer、选择与 gather 本身也有开销，不能把整个系统直接写成纯 O(T)。DeepSeek V3.2 与 GLM-5 的所核配置均给出 index_topk=2048。

Gated DeltaNet 则把历史逐步写入一个矩阵状态 S，而不是始终保存并读取全部位置。用简化的 delta rule 表示：先由 Sₜ₋₁ kₜ 读出旧状态对当前 key 的预测，再用 βₜ(vₜ−Sₜ₋₁kₜ)kₜᵀ 修正；另有遗忘门控制旧状态保留量，最后以 qₜ 从新状态读出输出。实际实现还有归一化、卷积和门控，不能把这条简式当作完整源码。decode 时状态大小不随上下文长度持续增长，但历史被压缩后，对某个旧 token 的精确寻址更难。

Qwen3-Coder-Next 与这里的 Qwen3.5 型号将 Gated DeltaNet 层和全注意力层交替布置：多数层用状态更新节约成本，少量全注意力层保留精确读取。这是不同层采用不同 mixer，不是同一层把两种注意力输出简单相加。“Attention gate”也应区分：它控制注意力输出的通过量；DeltaNet 的遗忘/更新门则控制历史状态。

MoE：每个 token 选几份前馈计算，而非把整模型切成多个聊天机器人

MoE 常常替换 block 的 FFN。输入仍是一个 d 维 token 向量，Router 根据它计算各专家分数，选择 Top-K。被选中的专家分别运行自己的 FFN，输出按路由权重合并回一个 d 维向量。如果有共享专家，它会始终参与。Attention、Norm 等公共主干仍照常运行；专家不是拥有独立上下文和对话能力的完整模型。

MoE(x) = Σᵢ∈TopK gᵢ(x) Eᵢ(x) + E_shared(x)没有共享专家的型号省略最后一项；路由打分与权重归一化细节因实现而异。

例如一个 MoE 层有 256 个路由专家，每 token 只选 8 个，意味着当前 token 只执行这 8 个专家的 FFN，下一 token 可能换一组。总参数衡量整个模型持有多少权重，激活参数衡量一次 token 计算动用了多少权重。Top-8 / 256 并不等于整个模型只激活 3.125%，因为还包括公共层、共享专家和前面的 dense 层。

稀疏激活减少前馈 FLOPs，却不意味着只需把 8 个专家加载进显存。不同 token 会路由到不同专家，部署通常仍需容纳整个权重集合并分布到多个设备；跨设备传 token 会产生 all-to-all 通信。某几个专家过热还会让其他设备等它们，拖慢尾延迟。负载均衡、路由偏置和专家并行是维持效率的关键。专家会在训练中形成某些偏好，但不能简单给第 7 个专家贴上“数学专家”的固定标签。

DeepSeek V3.2 · MLA + DSA

左侧仍是 MLA 和 MoE 组成的 Decoder-only 主干。变化落在注意力内部：Indexer 先决定当前 query 值得看哪些历史位置，再由主注意力处理这些位置的压缩 KV。所核 checkpoint 配置有 61 层、256 个路由专家、Top-8、1 个共享专家；index_topk=2048 表示稀疏选择的预算，不是上下文长度。

把 MLA 与 DSA 放在一起读：MLA 处理“每个历史 token 用多少缓存表示”，DSA 处理“当前 token 对哪些历史位置做主注意力”。压缩本身不跳过位置，稀疏选择本身也不保证 KV 已压缩。对很长的输入，减少主注意力的访问能节约计算；对短输入，选择器的额外开销占比可能更高。Indexer 选错重要证据时，主注意力不会凭空补回漏掉的信息。

官方 GitHub 仓库的 README 使用 V3.2-Exp 发布口径，而这里参数另对照 DeepSeek-V3.2 发布 checkpoint。图展示两者相关的 MLA + DSA 机制；实验版本与正式版本的后训练和评测不能互换。服务允许的上下文上限也应以实际发布说明为准。

Kimi K2 · MLA

Kimi K2 保留 MLA + MoE 的组合，61 层中仅第 1 层是 dense FFN；隐藏维度是 7168，注意力 heads 为 64。它把路由专家扩到 384 个，但每 token 仍选 8 个并经过 1 个共享专家。官方给出的总量是 1T、激活 32B。专家变多主要增加可选择的参数容量，并不会让单 token 同时运行全部专家。

把 K2 与 DeepSeek V3 的图对照，能看到容量、注意力头数和 dense 层数量分别是可调整的维度。“总量更大、激活更少”并不矛盾；但不同 head 尺寸、共享模块和层配置都会影响真实 FLOPs，不能只靠 32B 与 37B 判定谁更快。K2 的 Muon 优化器与工具行为训练属于训练方法，不是前向推理中多出来的模块。

原画板的 256K 与初版 checkpoint 不一致。本节核对的是 Kimi-K2-Instruct 初版，官方 README 和配置均给 128K（131072）；256K 应另对照相应更新版本，不能直接移植到初版。图保留同一结构，长度标注在正文按版本解释。

Qwen3-Coder-Next · Gated DeltaNet / Gated Attention

这张图里的关键变化在 token mixer：48 层中，每四层安排一层全注意力，其余使用 Gated DeltaNet。全注意力层有 16 个 Q heads、2 个 KV heads；DeltaNet 层更新自己的矩阵状态。两类层都接回残差主干，然后进入 MoE，512 个路由专家里选 10 个，另外有 1 个共享专家。80B 总参数与 3B 激活参数说明专家非常稀疏。

想象模型读取一个很长的代码仓库。多数层用有限大小的状态持续整合代码特征，少数全注意力层保留对旧位置的精确读取。这样同时降低部分层的历史存储和前馈成本，但全注意力层仍有 KV Cache；因此整个模型的缓存并没有完全消失。配置的原生长度是 262144，位置旋转只覆盖全注意力 head 的部分维度。

Coder-Next 基于 Qwen3-Next-80B-A3B-Base，编码与 Agent 能力还来自可执行任务合成、环境交互和 RL。能调用工具或修改代码，不能单独归功于 DeltaNet；需要把结构、训练数据和运行环境一起看。

Step 3.5 Flash · GQA / SWA

Step 3.5 Flash 使用 45 层、4096 隐藏维度的主干，前 3 层是 dense FFN，后面是 MoE：288 个路由专家选 8 个，外加共享专家。官方将约 196B 主干与额外 head 参数分开描述，总口径约 196.81B，每 token 激活约 11B。主干图里的 196B 是近似标注。

04 · 训练与后训练：相同骨架如何学出不同的行为

架构定义哪些运算能发生，权重决定具体如何运算，训练目标决定哪些输出会被鼓励。理解这三者的关系，就能分清“换了注意力”“做了微调”和“增加推理时间”分别改变了什么。

预训练与 SFT：从预测文本到学习目标回答

预训练在大量文本中做 next-token prediction，用交叉熵推动正确后续 token 的概率上升。每一步先前向算 logits 和 loss，再反向传播得到梯度，优化器更新权重。语言规律、知识关联和任务模式在这个过程中被统计地学进参数，但训练目标并不直接保证“遵守用户指令”或“事实可靠”。

SFT 使用指令与目标回答，让模型学习面对问题时怎样组织输出。聊天模板里的角色和特殊 token 要与 tokenizer 保持一致；模型依然在预测后续 token。只对 assistant 回答计 loss 时，把 system/user 对应的标签设为忽略值，但这些 prompt token 仍然参与前向计算，回答仍能看见它们。loss mask 决定哪里算误差，attention mask 决定哪里能读，两者不能互换。

输入：[system][user 问题][assistant 目标回答]标签：[忽略 prompt 的 loss] + [监督回答 token]忽略监督不等于从上下文删除。JSONL 只是存储容器，不决定这种计算语义。

知识管理场景中，训练数据可以同时包含检索证据、引用格式、工具调用和错误处理。只给成功的漂亮答案，会让模型学不到“没有证据就停止”“参数不合法就修正”。是否真的提升，需要在独立验证集上检查事实正确率、引用匹配和任务完成情况，不能只看训练 loss。

LoRA 改的是可训练参数，不是另一种奖励目标

对原来的线性层 y=Wx，LoRA 冻结 W，增加低秩更新 ΔW=(α/r)BA，其中 A 的形状为 [r,d_in]，B 为 [d_out,r]。训练中仅更新 A/B，前向变为 Wx+(α/r)BAx。若输入输出都是 4096、r=8，原矩阵约有 1678 万参数，而一组 adapter 只有 65536 个参数。这个算例只算一层，不是整个模型的总训练量。

LoRA 降低需要梯度和优化器状态的参数数量，但主模型仍参与前向与反向传播的相关计算，激活也要占显存。它可以与 SFT、DPO 等目标结合，因为“哪些参数可以更新”和“按什么目标更新”是两个独立维度。部署时可以合并增量到 W，或保留独立 adapter；量化主模型时还需注意合并与精度处理。

PPO 与 GRPO：生成候选后，用奖励推动策略变化

RL 的策略就是会生成回答的模型。对同一个问题，先由当前策略采样回答，运行奖励评估，再调整模型，使得到更高奖励的行为更容易出现。奖励可以来自奖励模型，也可以来自程序能验证的结果，例如数学答案、单元测试或工具任务成功。奖励只能表达设计者选定的标准，模型可能找到得分高却不符合真实目标的捷径。

PPO 使用价值估计构造 advantage，衡量某个动作比预期好多少。常见 RLHF 链路含 Actor、Critic、Reward 与 Reference：Actor 生成，Critic 估价值，Reward 评分，Reference 约束策略偏移。裁剪目标限制新旧策略概率比的变化，帮助稳定更新；它们是逻辑角色，是否共享底座或分布到不同设备依实现而定。

GRPO 对同一道题采样一组回答，用组内奖励作基准，典型简式为 Aᵢ=(rᵢ−mean(r))/(std(r)+ε)，从而不需要独立 Critic 来提供同样的基准。比如奖励为 [0,0,1,1]，成功样本相对本组均值更好，失败样本相对更差。若本组全部同分，相对奖励信号不足，不能凭空分辨哪条轨迹更值得鼓励。减少 Critic 不等于低成本：采样多个长回答、验证答案与同步策略都要花资源。

DPO：拿偏好对直接改变两个回答的相对概率

DPO 使用离线偏好数据 (问题 x, 更好回答 y⁺, 较差回答 y⁻)。它比较当前策略相对于 reference 的对数概率增益，让被偏好的回答比另一个回答获得更大增益。一个常见写法是下面这个式子；p 是整段回答在条件 x 下的概率，实际由回答 token 的对数概率求和得到。

Δ = [log pθ(y⁺|x) − log pref(y⁺|x)]　 − [log pθ(y⁻|x) − log pref(y⁻|x)]ℒ_DPO = −log σ(βΔ)提升 chosen 相对 reference 的概率优势，抑制 rejected 的相对优势。

它省掉了经典在线 RL 流程中的显式奖励模型训练和 rollout 环节，但仍需要可靠偏好对与 reference 设定。离线数据没有覆盖的场景，不能期待模型自动学到正确选择；偏好只表达“这两个里更喜欢哪个”，也不保证更喜欢的回答没有事实错误。

把训练放回工程：预算、评测与实际能力

Micro-batch 小时，可以累计多个 micro-batch 的梯度再更新一次。有效 batch 通常为 micro_batch × accumulation_steps × data_parallel_size；需要正确缩放 loss，避免累计次数变化也改变更新幅度。它能缓解单步显存压力，但不消除每个 micro-batch 的激活开销，也不等价于把所有样本放进一个前向过程中的所有统计行为。

学习率 warmup、衰减、梯度裁剪和检查点用于控制训练稳定性、记录回退点。最终比较应该固定数据版本和推理条件，分别看能力、行为和成本。更长的“思考文本”属于推理阶段增加计算；只有后续把这些轨迹用于训练并更新权重，才会改变模型参数。工具调用能力既可以通过训练改善，也可以受运行时 schema 和反馈影响，不能全部归因于某个 RL 算法。

05 · 接入 Agent：模型计算如何变成可执行的系统动作

现在把模型放进知识管理应用。用户问“查一下这周某项目的风险，并整理依据”，模型的一次前向计算只产生下一段文本或工具调用请求；真正读数据库、记录状态与决定停止的是外部运行时。

工具调用把一次预测接到一个真实执行过程

应用给模型提供工具名、用途和参数 schema，例如 search_project(project_id, time_range)。模型生成结构化调用，运行时解析后检查字段、参数类型与当前权限，才真正调用检索服务。得到文档后，把带来源和时间的信息作为 tool message 放回上下文，模型再决定是否补查或组织答案。因此模型没有因为“输出一个函数名”就在自己的神经网络里执行函数。

若检索只返回了过期周报，系统应该让模型感知缺失范围；若参数校验失败，应返回明确的错误并限制重试。回答阶段要检查引用是否指向真实检索结果、结论是否被证据支持。约束解码能够保证部分语法或 schema 格式，但无法单独保证项目 ID 正确、权限充分或事实真实。

上下文、权重知识与工作流状态是三份不同的信息

模型权重保存训练形成的统计关联，通常不会因一次工具调用而更新；上下文携带当前对话、工具描述与文档证据；工作流状态保存在应用里，包含已经确认的事实、待完成步骤、工具结果、预算和错误记录。把全部状态只写成一大段聊天历史，会让临时猜测和已验证事实混在一起，也不便恢复和重放。

一个可靠的 Agent loop 可以按“提出动作 → 校验 → 执行 → 观察 → 更新状态”运行，达到证据充分、预算用尽或无法继续时停止。模型判断“需要补查”只是候选决策；运行时仍应强制执行工具次数、时间上限和权限约束。长上下文和更强 reasoning 有助于处理复杂信息，却不能代替这些显式的状态与停止规则。

JEV / System One：公开定位与系统层解释分开读

TypeSafe 的 System One / JEV 公开介绍强调类型化决策、概率与置信度的表达。当前材料不足以在这里绘制其内部神经网络，也不足以断言它采用哪种 attention、公开了哪些权重或怎样校准分数。因此，上图表示通用 Agent 运行时，不冒充 JEV 的内部架构。

在通用系统设计中，可以把这种思路理解成一份决策协议：模型输出候选，控制层把结果整理成明确的动作类型，例如 Answer、SearchMore、Escalate，附上证据、缺失条件和经过校准的分数，再由执行器处理。类型帮助检查字段与合法状态；分数是否可当作可靠概率，需要用实际样本验证校准。模型自报的“置信度 90%”不会自动成为正确率 90%。

对知识管理系统，最有用的连接是：架构决定计算与缓存成本，训练影响检索、引用和工具行为，运行时保证权限、状态和可追溯执行。只有把三层接起来，才可以解释为什么某个模型在真实工作流里表现更好，以及问题究竟应该在模型、数据还是系统里修正。
