# 八股题库视觉结构设计

## 目标

将八股题库从统一的纯文字卡片重构为“一个问题一个板块”的结构。保留每道题的标准文字答案，只对适合表达机制、架构或执行链路的题目增加原生 HTML/CSS/SVG 图示，避免把所有题目都做成图，也避免使用折叠内容。

## 页面结构

每道题包含：问题标题、一个完整的 `Answer` 标准答案，以及可选的图示。答案不再拆成“Answer + 补充”，也不使用动态追加的逐字稿或补充段落。

题目按类型渲染：

- `text`：普通定义题，保持两列网格。
- `flow`：流程题，通栏展示文字和执行流程图。
- `architecture`：架构题，通栏展示文字和模块关系图。
- `comparison`：比较题只保留文字答案，不额外画表或图。

普通题继续使用紧凑双列布局；适合图示的题目占满一行。移动端统一变为纵向排列，保证节点、文字和箭头不重叠。

## 图示范围

使用原生 HTML/CSS，必要时使用内联 SVG 连接线，不引入 Mermaid 或外部脚本。

- Function Calling：工具声明、模型选择、参数校验、执行、结果回传、继续调用或结束。
- ReAct：目标、决策、动作、观察、状态更新、终止判断。
- MCP：Host/Agent、Client、Server 三层，以及 tools、resources、prompts 的边界。
- Agent 架构：模型、路由、规划、工具、记忆、状态和治理。
- 上下文和记忆：内容分层、优先级、短期/长期记忆关系。
- 工具管理：大量工具、路由、动态加载和执行边界。
- RAG：文档处理、索引、查询、召回、重排、上下文组装、生成。
- Transformer/MoE：自注意力计算、MoE 路由和专家合并。
- 缓存/数据库：多级缓存读写、快照读和当前读的机制关系。

list/tuple、`==`/`is`、SSE/WebSocket、Redis 类型、事务隔离级别等比较或基础题保持文字表达。

## 实现方式

将八股题目整理为题目数据和渲染器。每条数据包含 `id`、`type`、`question`、`answer` 和可选的 `visual`。渲染器根据题型添加布局 class，并调用对应的原生图示组件。删除当前 `scriptAnswers`、`enrichKnowledgeAnswers` 和动态“补充”逻辑，把完整答案收回题目数据自身。

业务面、主管面、HR 面以及两个原始 HTML 的完整正文保持不变。

## 验证标准

1. 53 道题和 53 个标准答案全部保留。
2. 普通题为双列，图示题为通栏，移动端自动纵向排列。
3. Function Calling、MCP、RAG 等重点图示正常渲染。
4. 页面不出现八股题折叠控件、重复的“补充”区块或逐字稿文案。
5. 图示文字不重叠，GitHub Pages 与本地静态文件均可打开。
