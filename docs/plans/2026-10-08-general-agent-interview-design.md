# 通用 Agent 开发岗面试复盘与话术设计

日期：2026-10-08。状态：用户已确认设计结构，完整私有稿已在面试资料目录整理。

## 目标与范围

面向不同公司的 Agent 应用开发岗位，将既有知识材料转为可口述、可深挖、可验证的面试结构。覆盖自我介绍、业务查询 Agent、VLM 评测、学校 RAG 系统与 SG-FKE 方法研究、意外追问、编码需求复述和反问。

三个项目独立形成完整闭环，不使用一个主项目贯穿、另外项目仅作支撑的结构。面试官决定项目顺序与深度；候选人通过准确、可承担验证的表达引导相关追问。

## 四层深度

1. 约 15 秒：项目定位、个人范围与一个关键机制。
2. 约 60–90 秒：问题、本人责任、链路、取舍、结果与边界。
3. 约 3 分钟：围绕具体机制解释输入、控制位置、数据变化、异常与验证，不重复背景。
4. 两层追问：机制解释之后处理反例，绑定来源和实现范围，并设计停止点。

## 内容组成

- 三场原始面试的证据复盘：对照提问目的、原回答造成的追问与改进答法，区分面试官反馈、同伴反馈和候选人感受。
- 三项目地图式自我介绍：实习与学校经历准确分开，每项主动主张都有预期追问与证据。
- 每个项目的独立短、中、长版本，以及两层追问卡。
- 真实失败与设计推演分别标注，结果口径与个人职责分开，冲突材料留核对项。
- 面前速练卡：开场、链路、关键数字、反例、修复话术和复练顺序。

## 处理错误与未知

回答当前问题，守住给定前提；发现理解偏差时区分对象；自己表述错误时局部修正。没有做过的能力，先说明现状，再讨论设计与验证。多源材料完成状态不一致时，不用话术推定实现或上线。

## 验证标准

检查三个项目的独立闭环与两层追问是否齐全；数字是否保留数据单位、比较条件和分母；来源路径是否可访问；主回答是否把团队成果、框架已有能力或未来研究归给个人；时间只作试讲目标，需录音实测。

复练随机项目顺序、打断和改变前提。评分覆盖当前问题、个人责任、机制、验证、反例与节奏；先消除缺项，再优化表达流畅度。
