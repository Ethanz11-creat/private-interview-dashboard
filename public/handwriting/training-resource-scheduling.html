01 · 先明确选择与目标

完整题干

P5346. 第 2 题 — 双配置训练任务的最优资源调度 难度：5 所属公司：华为

一个模型训练集群需要依次执行 n 个任务。对于任意第 i 个任务，调度系统给出两套候选配置，它们在计算资源占用和训练耗时上各有差异。

采用配置 1 时，资源消耗为 c₁，训练耗时为 t₁；采用配置 2 时，资源消耗为 c₂，训练耗时为 t₂。资源统一按“CPU 核心数 + GPU 显存 GB”计量，集群可使用的总资源量为 C。

现在为每个任务选定一套配置，每个任务只能且必须选择两套之一。所有任务资源消耗的总和不得超过 C。在合法选择中，目标是最小化所有任务的总训练耗时，并确定最优方案实际使用的资源量与剩余资源量。

如果多个合法方案的最小总耗时相同，选择其中实际资源消耗最少的方案。

约束条件

  • 1 ≤ n ≤ 100。
  • 1 ≤ C ≤ 1000。
  • 每个任务的 c₁、t₁、c₂、t₂ 均为 1～100 的正整数。

输入描述

第一行是两个整数 n C，分别为任务数量与资源上限。接下来的 n 行，每行四个整数 c₁ t₁ c₂ t₂，依次表示该任务两套配置的资源与耗时。

输出描述

输出三个整数，用单个空格分隔：最小总耗时、在该最小耗时下的最小实际资源量、C 减去实际资源量后的剩余资源。

本题虽然写“依次执行”，资源约束仍按题目规定计算为各任务消耗的总和。实现时不把它改成资源峰值，也不引入并行调度或任务重排。

样例 1

输入

3 10
4 5 2 3
3 4 5 2
1 2 2 2

输出

7 8 2

任务 1 选配置 2：(资源 2，耗时 3)；任务 2 选配置 2：(资源 5，耗时 2)；任务 3 选配置 1：(资源 1，耗时 2)。总耗时 3+2+2=7，总资源 2+5+1=8，剩余 10−8=2。

每个任务独立的最小耗时之和也是 7，已经达到耗时的理论下界。任务 3 两种配置耗时都为 2，配置 1 资源更少，因此选择配置 1。

样例 2

输入

1 1
1 5 2 3

输出

5 1 0

资源上限是 1，配置 2 的资源 2 超限。唯一合法选择为配置 1，耗时 5，使用资源 1，剩余 0。

样例 3

输入

2 5
3 4 2 6
2 5 4 1

输出

9 5 0

两个任务都选配置 1：资源 3+2=5，耗时 4+5=9。任务 1 配置 2、任务 2 配置 1 虽然只用 4 单位资源，但耗时 11 更大。只要任务 2 选配置 2，就会超过容量。

样例 4

输入

3 1000
10 20 5 25
3 15 4 15
6 7 2 12

输出

42 19 981

资源充足，各任务均选择配置 1：耗时 20+15+7=42，资源 10+3+6=19，剩余 981。任务 2 两配置耗时相同，优先选资源少的配置 1。

原解析中的数字纠正：你提供的解析写“样例 1 有耗时 8、资源 14 和 15 的方案”，这与题干数据不符，而且 14、15 都超过容量 10。正确的两个同耗时最优候选是 (耗时 7，资源 8) 和 (耗时 7，资源 9)，最终选择资源 8。
题干未规定无解输出：现有约束不保证一定可行。例如 n=1、C=1，两配置资源为 2 和 3 时，无法完成任务。下面参考代码可以识别无解状态，但原 main 没有专门处理。此处不自行添加“输出 −1”等规则；若实际题目存在无解测试，需要以平台规定为准。
02 · 从搜索走向动态规划

核心模型：每组必须选一个的分组背包

把每个任务看成一组，组里有两种配置。资源是容量消耗，耗时是要最小化的代价。与可选或不选的普通 0-1 背包不同，这里不能跳过整组，也不能同时选同组两种配置。

为什么不直接枚举或贪心？

每个任务二选一，一共有 2ⁿ 种完整方案。DFS 枚举选择的时间为 O(2ⁿ)，n=100 时不可行。

逐任务选择耗时最小的配置也不总合法。例如两个任务都提供 (资源 2，耗时 1) 与 (资源 1，耗时 5)，容量 C=3。两次都选最快配置要资源 4，超限；正确做法是其中一个任务选快配置，另一个选慢配置，得到耗时 6、资源 3。局部最优选择不能独立决定全局方案。

1. 状态定义

dfs(i, used) = (best_time, best_extra_cost)

i 表示已经处理完前 i 个任务，接下来处理下标 i 的任务；used 是前面已经用掉的资源。函数返回的是从任务 i 到末尾的最优后缀结果：

  • best_time：剩余任务的最小额外耗时。
  • best_extra_cost：达到该额外耗时所需的最小额外资源。
两个资源量不要混淆：used 是进入状态前已经占用的资源；返回的 cost 是从当前任务开始还要新增的资源。只有在起点 dfs(0,0)，返回 cost 才正好等于整个方案使用的资源。

为什么只需要 (i,used)，不用记录历史配置与过去耗时？

剩余哪些任务由 i 决定，还能使用多少容量由 C−used 决定。进入同一个状态后，未来任务及其约束完全一致，过去怎么选不再影响后续计算。

过去耗时可以在回溯时相加，不必放进缓存。不同路径即使到达同一状态时累计耗时不同，仍可以复用相同的最优后缀。

示意路径前两任务配置已用资源已用耗时
路径 A任务 0 选 (1,1)，任务 1 选 (2,5)36
路径 B任务 0 选 (2,3)，任务 1 选 (1,2)35

示意数据：这两行来自两个任务分别拥有的两套配置，并非原题样例。两条路径都到达 dfs(2,3)。假设 C=4，最后任务可选 (资源 1，耗时 4) 或 (资源 2，耗时 1)，那么相同的后缀结果都是 (4,1)；两条完整路径总耗时分别是 10 和 9。

2. 边界与不合法状态

i==n 时所有任务都已完成，后续耗时与后续资源都为 0，返回 (0,0)。

每次递归前都检查 used+c≤C，超容量的分支不调用。因为资源消耗都是正数，超限后不会通过后续选择重新变合法。原代码从 (0,0) 开始，入口检查已经保证 used 始终在 [0,C]，不必再在 dfs 内写 used>C。

如果两种配置都没有可行后续，当前状态保持 (INF,INF)。不能把它当成 (0,0)，否则相当于允许后续任务不执行。

3. 状态转移

当前任务两套配置为 (c₁,t₁)、(c₂,t₂)。对于任一可行配置 (c,t)：

(next_time,next_cost) = dfs(i+1,used+c)
candidate = (t+next_time, c+next_cost)
dfs(i,used) = 所有合法 candidate 中，按 (耗时,资源) 排序的最小者

若 next_time==INF，说明这个选择无法完成全部剩余任务，不能参与候选比较。

4. 两级目标如何比较？

if cur_t < best_t or (cur_t == best_t and cur_c < best_c):
    best_t = cur_t
    best_c = cur_c

先比耗时，耗时相同再比资源。这是按 (time,cost) 的字典序取最小，Python 元组比较也遵循相同规则。不能把两个目标简单相加；两者不是同一优先级。

固定状态时前缀 used 相同，因此比较后续新增资源 c 就等价于比较最终总资源 used+c。

5. 缓存重复状态

memo[i][used] 保存已经算出的最优后缀。None 表示还没算，(INF,INF) 表示已经算过但无解，两者必须区分。每个状态最多计算一次，后续访问直接返回缓存。

样例 1：按一条最优路径回溯

状态该路径的选择后缀返回值含义
dfs(3,8)全部任务完成(0,0)无需额外时间与资源
dfs(2,7)任务 3 选 (1,2)(2,1)两配置同耗时，选资源 1
dfs(1,2)任务 2 选 (5,2)(4,6)2+2=4；5+1=6
dfs(0,0)任务 1 选 (2,3)(7,8)3+4=7；2+6=8

表格展示计算结果如何沿最优路径回传；实际 DFS 也会检查其他合法分支，比较后确定最优，而不是预先只走这条路径。

正确性说明

  1. 边界 i=n 返回 (0,0)，符合“没有剩余任务”的真实最优值。
  2. 任何合法完整方案在当前任务都必须选配置 1 或 2，两个递归分支覆盖全部合法情况。
  3. 假设下一层返回最优后缀，把当前配置的耗时与资源加上，就得到以该配置开头的最优候选。
  4. 按 (耗时,资源) 比较两候选，得到当前状态的最优值；逐层回推，dfs(0,0) 就是全局最优。

复杂度

项目复杂度理由
状态数量O(nC)i 有 n+1 种；used 有 C+1 种
总时间O(nC)每个非终点状态最多尝试两种配置，缓存表初始化也是 O(nC)
缓存空间O(nC)预分配 (n+1)×(C+1) 个格子
递归栈O(n)每次递归 i 加 1，最多 n+1 层
总额外空间O(nC)缓存与递归栈相加，C≥1 时由缓存占主导

n≤100、C≤1000，表格最多 101×1001=101101 个格子，约 10⁵。不是每个格子都会被访问，但这份代码会预先创建整张缓存表。

03 · 参考实现

Python 记忆化搜索代码

保留你提供的算法与输入输出流程，省略重复注释。在存在合法完整方案时，输出题目要求的三个整数。无解时的接口缺口见下方说明。

import sys

INF = 10 ** 9


def solve(n, C, a):
    # memo[i][used] 保存状态的最优结果
    # 每个结果为 (最小耗时, 对应的最小额外资源)
    memo = [[None] * (C + 1) for _ in range(n + 1)]

    def dfs(i, used):
        # 所有任务已经处理完成
        if i == n:
            return 0, 0

        # 当前状态已经计算过，直接返回
        if memo[i][used] is not None:
            return memo[i][used]

        best_t = INF
        best_c = INF
        c1, t1, c2, t2 = a[i]

        # 当前任务选择配置 1
        if used + c1 <= C:
            nt, nc = dfs(i + 1, used + c1)
            if nt != INF:
                cur_t = t1 + nt
                cur_c = c1 + nc
                if cur_t < best_t or (cur_t == best_t and cur_c < best_c):
                    best_t = cur_t
                    best_c = cur_c

        # 当前任务选择配置 2
        if used + c2 <= C:
            nt, nc = dfs(i + 1, used + c2)
            if nt != INF:
                cur_t = t2 + nt
                cur_c = c2 + nc
                if cur_t < best_t or (cur_t == best_t and cur_c < best_c):
                    best_t = cur_t
                    best_c = cur_c

        memo[i][used] = (best_t, best_c)
        return memo[i][used]

    return dfs(0, 0)


def main():
    input = sys.stdin.readline
    n, C = map(int, input().split())
    a = []
    for _ in range(n):
        c1, t1, c2, t2 = map(int, input().split())
        a.append((c1, t1, c2, t2))

    min_t, used = solve(n, C, a)
    print(min_t, used, C - used)


if __name__ == "__main__":
    main()

代码中的几个关键点

代码作用
INF = 10 ** 9表示无解。合法总耗时最大 100×100=10000，远小于 INF。
[[None] * (C+1) for _ in range(n+1)]每行独立创建，防止二维列表各行共享引用。
if i == n终点先返回，未读取 a[n]。终点不缓存，返回仍是常数时间。
memo[i][used] is not None已计算状态直接复用，包括已知无解状态。
if used + c ≤ C保证递归参数与缓存下标合法，提前剪掉超容量选择。
if nt != INF剩余任务必须能全部完成，才拼接当前配置。
cur_c = c + nc返回的是后缀资源，不要再把前缀 used 加进返回值。
C - usedmain 中 used 是 solve 返回的最优全局资源，计算剩余容量。
无解时不能直接使用原 main 输出：solve 会返回 (INF,INF)，原 main 将打印巨大哨兵值和负剩余资源，这不是题干定义的正常答案。可以先判断 min_t==INF，但无解分支应该输出什么，需要平台给出规则；本页没有伪造一种标准输出。

是否存在合法方案，可以提前确定

minimum_resource = sum(min(c1, c2) for c1, t1, c2, t2 in a)
# minimum_resource > C：一定无解
# minimum_resource <= C：至少“每任务选资源最小配置”是一个合法方案

这个判断只用于可行性，不代表它得到最小耗时。原 solve 已能判定无解，因此预检查不是正确性的必需步骤。

04 · 面试时怎样讲清楚

先说建模，再说状态与优先级

约 30 秒口述

“这题可以看成分组背包：每个任务是一组，每组必须从两种配置里选一个，容量是总资源。我用记忆化搜索，状态是当前任务位置和已用资源，返回剩余任务的最小耗时，以及同耗时下的最小额外资源。每个状态尝试两个配置，超容量的直接跳过，按耗时优先、资源次之比较结果。最终从 dfs(0,0) 得到答案。时间和空间都是 O(nC)。”

约 1～2 分钟展开

“直接搜索每个任务的两个配置有 2ⁿ 种方案，n=100 时太多。关键观察是：到了同一个任务位置，如果已用资源也相同，那么剩余任务和剩余容量完全一致，后续最优决策可以复用。

因此定义 dfs(i,used)，表示已经做完前 i 个任务、资源用了 used，后续任务的最优结果。它返回两个值：剩余任务的最小耗时，以及达到这个耗时时需要的最小新增资源。过去耗时不放进状态，因为回溯时会把当前配置的耗时逐层加回来。

对于当前任务的每个配置，只要 used+c 不超容量，就递归下一任务。如果后续有解，就得到候选 (t+next_time,c+next_cost)。两个候选先比耗时，耗时相同再比资源。这是字典序比较，也满足题目的二级目标。

所有任务处理完成时返回 (0,0)。两个分支都无法完成时返回无解标记。用 memo 缓存每个状态，最多 n(C+1) 级别的状态，每状态只有两次转移，所以时间 O(nC)，缓存 O(nC)，递归栈 O(n)。最后返回最优总耗时、总资源，以及 C 减去总资源。题干如果允许无解，还需要明确无解的输出格式。”

常见追问与回答

1. 为什么不是普通 0-1 背包？

普通 0-1 背包通常允许不选某个物品；这里每个任务必须完成，必须在同组两配置中选一个。若允许跳过任务，最小耗时会被错误地算成 0。

2. 为什么不记录“已用耗时”？

过去耗时不改变后续的资源限制或可选配置。函数专门返回后缀最优值，前缀耗时在回溯时相加，因此不同前缀能共用同一个后缀缓存。

3. 为什么返回资源是额外资源，而不是 used+额外资源？

这个函数的返回值语义是“剩余任务贡献多少”。父状态会再加自己的配置资源；若每层都把 used 加进去，就会反复计算过去的资源。起点 used=0，所以根状态返回的额外资源正好是总资源。

4. 同耗时优先少资源，能不能靠遍历顺序实现？

不能。先遍历的方案不一定资源更少，必须在比较条件中显式处理 cur_t==best_t 时的资源大小。比较 (time,cost) 元组也可以。

5. 可以改成迭代 DP，并优化到 O(C) 空间吗？

可以。令 dp[r] 为已完成当前任务前缀、恰好使用 r 资源的最小耗时。初始 dp[0]=0，其他为 INF。每处理一个任务，新建全 INF 的 ndp，从上一层的每个可达 r 分别转移两配置，完成后 dp=ndp。不能简单保留旧 dp 表示跳过这个任务。

最后在 r≤C 中寻找耗时最小者，耗时相同选择最小 r。两层滚动数组空间 O(C)，时间 O(nC)。资源 r 本身就是状态下标，因此每个格子只需保存耗时。

6. 如果要输出每个任务选哪套配置呢？

题目目前只要求三个汇总值，不需要保存完整选择。若新增方案输出要求，可以记录每个状态采用的配置编号，之后从 (0,0) 按选择更新 i 和 used，依次还原；存在同耗时同资源的方案时任取即可，除非题目再规定额外顺序规则。

7. 怎么快速确认无解？

每任务的最小资源之和若超过 C，一定无解；若不超过 C，直接选择每个任务的最小资源配置，就构成一个合法方案。因此这是本题可行性的充要条件。但最小资源方案未必最省时间，仍需要 DP 求最优目标。

8. 为什么这题不需要排序、调换任务顺序？

耗时与资源是所选配置的加总，且没有任务之间的依赖、切换成本或并发约束。原顺序只用于按任务推进 DP；重新排序不会改善配置组合的目标值。

面试讲解的关键：准确说清“每任务必选一个”“后缀结果不含前缀”“先最小耗时，再最小资源”，然后说明相同 (i,used) 的未来为何一致。比单纯背诵“记忆化 O(nC)”更能说明你理解了状态。
