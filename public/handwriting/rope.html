01 / 原题整理

输入、位置与返回值

给定一个二维特征矩阵 X 和每一行对应的位置，使用 Rotary Position Embedding（RoPE）为每个 token 注入位置。输出仍是与 X 同形状的矩阵。

接口和形状
参数形状意义
X / x(T,D)T 个 token，每个 token 有 D 个特征；D 必须为偶数
positions(T,)每一行的位置；省略时使用 0,1,…,T−1
base标量 > 1频率底数；代码默认 10000，演示使用 100 让旋转更明显
output(T,D)每一对通道独立旋转后的矩阵

演示输入（完整保留）

X = [[1, 0, 0, 1],
     [1, 1, 1, 0],
     [0, 1, 2,-1]]
positions = [0, 1, 2]
base = 100

因为 D=4，所以每个 token 有两对二维坐标：(x[0], x[1]) 和 (x[2], x[3])。位置 0 的角度全为 0，因此第一行保持不变；位置 1、2 会分别转动。

输出（六位小数）

[[ 1.000000,  0.000000,  0.000000,  1.000000],
 [-0.301169,  1.381773,  0.995004,  0.099833],
 [-0.909297, -0.416147,  2.178736, -0.582727]]

这组数值使用 base=100 便于观察；base=10000 时第二对通道的角度变小，但计算流程完全相同。实现不会把输出截断到六位小数。

约束与边界

  • D 必须是偶数，否则无法把通道两两组成二维旋转平面。
  • positions 长度必须等于 T，可以是不连续位置，例如缓存推理时的 [8,9,10]。
  • base 必须大于 1；不同 base 会改变各通道的频率尺度。
  • RoPE 本身不改变矩阵形状，也不做归一化；输出数值可以为任意实数。
02 / 先理解二维旋转

不是给整行乘一个位置向量，而是每两维转一次

原始 token 向量

x = [x₀, x₁, x₂, x₃]
       └── pair 0 ──┘ └── pair 1 ──┘

相邻通道组成二维坐标。RoPE 不把位置 embedding 直接加到 x 上。

→

位置决定两组角度

θ₀(p) = p × 1
θ₁(p) = p × base⁻²⁄ᴰ

低下标通道变化快，高下标通道变化慢；同一 token 的两对通道使用不同频率。

→

分别乘二维旋转矩阵

[x′₂ᵢ  ]   [ cosθ  −sinθ ] [x₂ᵢ  ]
[x′₂ᵢ₊₁] = [ sinθ   cosθ ] [x₂ᵢ₊₁]

旋转改变方向，保持每一对坐标的平方范数。

位置 p=0θ = [0, 0]

cos=1、sin=0，所以 x′=x。

位置 p=1θ = [1, 0.1]（base=100,D=4）

第一对转 1 弧度，第二对只转 0.1 弧度。

位置 p=2θ = [2, 0.2]

位置翻倍，角度也翻倍；不同频率的两对通道会形成不同相位。

和绝对位置向量的区别：RoPE 把 position 变成旋转角度，并作用在 Q/K 的通道对上。两个位置旋转后的点积会自然携带相对位置信息；没有额外把一个可学习或固定向量加到 token 表示上。
03 / 公式对应代码

频率 → 角度 → 旋转

1. 每一对通道的逆频率

inv_freqi = base−2i/D，i = 0,1,…,D/2−1
θp,i = positionp × inv_freqi

代码用 np.arange(0,D,2) / D 生成 0/D、2/D、4/D……，等价于公式中的 2i/D。第一对的 inv_freq 永远为 1；越往后的通道频率越低，旋转越慢。

2. 二维旋转公式

x′p,2i = xp,2icosθp,i − xp,2i+1sinθp,i
x′p,2i+1 = xp,2isinθp,i + xp,2i+1cosθp,i

代码里的 even = X[:,0::2] 取出每对的第一个坐标，odd = X[:,1::2] 取出第二个坐标；两个矩阵形状都是 (T,D/2)，可以与 cos、sin 逐元素相乘。

3. 为什么范数不变？

(x′2i)² + (x′2i+1)² = x2i² + x2i+1²

旋转矩阵是正交矩阵，cos²θ+sin²θ=1，交叉项相互抵消。它只改变二维向量的方向，不放大或缩小该对通道的长度；页面下方会把旋转前后的每对范数列出来。

4. 角度的单位

代码中的角度是弧度。np.sin 和 torch.sin 都按弧度计算；不能把 position 直接当成角度后再转成度数，也不需要手动乘 π/180。

06 / 接入 Attention

实际模型为什么只旋转 Q 和 K？

Q
内容 + 当前查询位置
→
K
内容 + 可匹配的位置
×
V 不旋转
保留被读取的内容

在 self-attention 或 decoder self-attention 中，通常先得到 Q、K、V，再只对 Q、K 的最后一维应用 RoPE：

Q_rot = apply_rope(Q, positions, base)
K_rot = apply_rope(K, positions, base)
scores = Q_rot @ K_rot.T / sqrt(d_head)
attention = softmax(scores, axis=-1)
H = attention @ V

Q 和 K 参与点积，旋转后点积会随两个位置的相对差异变化；V 是被加权读取的内容，通常不携带这一步的旋转。不要把 V 也旋转后再声称这是标准 RoPE attention。

为什么能表示相对位置？

二维旋转满足 R(θ₁)TR(θ₂)=R(θ₂−θ₁)。因此，\(R(m)q\) 与 \(R(n)k\) 的点积可以化成一个只依赖相对角度 n−m 的关系，再和内容向量的点积结合。

为什么只对 Q/K 的部分维度？

真实模型通常按 head 处理形状 (batch, heads, T, d_head)，并可设置 rotary_dim < d_head。先旋转前 rotary_dim 维，剩余维度直接拼回；本页的基础题把整个 D 都作为 rotary_dim。

和绝对位置编码对比：绝对位置编码常把位置向量加到 token 表示上；RoPE 将位置作为 Q/K 的相位旋转。它不增加最后一维，缓存推理时只需要根据 position id 生成对应的 cos/sin。
07 / 维度与语法

切片、广播和位置轴

1. `0::2` 和 `1::2` 到底取了什么？

X · (3,4)
[[1,0,0,1],
 [1,1,1,0],
 [0,1,2,-1]]
X[:,0::2] · 偶数列
[[1,0],
 [1,1],
 [0,2]]
每一对的第一个坐标
X[:,1::2] · 奇数列
[[0,1],
 [1,0],
 [1,-1]]
每一对的第二个坐标

切片 `start:stop:step` 中，`0::2` 表示从第 0 列开始每隔 2 列取一次；`1::2` 从第 1 列开始。两者形状都是 (T,D/2)，正好和一组 cos/sin 角度相乘。

2. 广播如何把一维频率扩展成每个位置的角度？

pos[:, None]          # (T,) → (T,1)
inv_freq[None, :]     # (D/2,) → (1,D/2)
angles = pos[:,None] * inv_freq[None,:]  # (T,D/2)

第 p 行的 position 乘上整行频率，得到该 token 每一对通道的角度。这里没有复制 Python 循环；NumPy / PyTorch 通过广播让 (T,1) 和 (1,D/2) 组合成 (T,D/2)。

3. `empty_like` 为什么不是全零？

np.empty_like(X) 或 torch.empty_like(X) 只分配与 X 同形状、同 dtype 的空间，不初始化值。随后两条赋值语句分别写入偶数列和奇数列，所以最终所有位置都会被覆盖；如果忘记其中一条赋值，输出可能包含未定义值。

4. 为什么有些源码写 `rotate_half`？

本页把相邻通道配成 (x₀,x₁)、(x₂,x₃)，所以直接写 even / odd 公式。另一些实现把同一组坐标排成“前半维 + 后半维”，例如 [x₀,x₁,x₂,x₃] = [a₀,a₁,b₀,b₁]，此时会写：

def rotate_half(x):
    half = x.shape[-1] // 2
    return torch.cat((-x[..., half:], x[..., :half]), dim=-1)

# half-split 布局下：x_rot = x * cos + rotate_half(x) * sin

rotate_half 做的是每个二维平面的 (a,b) → (−b,a)。它和本页的显式偶数列 / 奇数列公式表达同一个旋转，但前提是通道布局一致。面试手撕时先说清楚采用 interleaved（相邻配对）还是 half-split（前后半区配对），不要把两种布局的 cos、sin 直接混用。

08 / 盲写与自检

位置 → 频率 → 角度 → 成对旋转

T, D = X.shape
inv_freq = 1.0 / (base ** (np.arange(0, D, 2) / ______))
angles = positions[:, ______] * inv_freq[______ , :]
cos = np.______ (angles)
sin = np.______ (angles)
even = X[:, ______]
odd = X[:, ______]
out = np.______ _like(X)
out[:, 0::2] = even * cos - odd * sin
out[:, 1::2] = even * sin + odd * cos
return out.______()
展开答案与自检点
  • 频率分母用 D；positions[:,None] 与 inv_freq[None,:] 广播成 (T,D/2)。
  • 函数是 np.cos、np.sin、np.empty_like、out.tolist；切片是 0::2 和 1::2。
  • 位置 0 的输出必须和输入相同。
  • D 为奇数要明确报错；不能静默丢掉最后一列。
  • 每一对通道的平方范数在旋转前后相同。
  • Attention 接入时旋转 Q/K，V 保持原值；Q/K 的位置可以是显式 position ids。
  • 标准模型常用 base=10000，演示用 base=100 只是为了让第二对通道的角度肉眼可见。

复杂度

对 (T,D) 输入生成角度、sin/cos 和旋转结果都需要 O(TD) 时间与 O(TD) 中间空间。预先缓存给定最大长度的 cos/sin 后，推理时可以复用它们；RoPE 不增加 Q/K 的最后一维。
